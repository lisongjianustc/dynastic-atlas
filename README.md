# Dynastic Atlas · 历代疆域

一条可以拖动的年份游标，一张中国历代及周边政权疆域地图，一屏看懂「哪一年、谁在哪、控制到什么程度、发生了什么」。

**[在线看 →](https://lisongjianustc.github.io/dynastic-atlas/)**

**当前状态：可跑的交互应用 + 有内容的阶段性数据 + 显式的缺口清单。**
视野 200–960 年（三国魏晋 → 隋唐）：**39 政权 / 54 疆域段 / 82 事件 / 67 处城关 / 22 来源 / 69 个状态区间**。

**不能把当前地图用于引用完整古代疆界。** 全部疆域段的空间精度为 `approximate`，
全部记录的审查状态为 `pending` —— 未经历史专业审定。**空白表示尚缺资料，不表示当时没有政权或事件。**
点右上角「资料覆盖」可以看到完整的缺口清单。

## 与 HistoryMapV2 的关系

同目录下的 `HistoryMapV2` 是一个平行项目（由 codex 做到一半）。它**内容极少**——32 个政权、
23 个事件、**0 条正式疆域**——但**方法学严谨**，并且明确拒绝把自己版本的示意边界升格成史实
（「旧版 HistoryMap 的示意边界未直接升级为史实」）。

这个判断是对的。本项目吸收了它的**治理模型**，并把它落到有内容的数据上：

| 吸收的东西 | 在本项目的落地 |
|---|---|
| 每条主张带出处定位 | `evidence: [{sourceId, locator, note}]`，至少一条，构建期强制 |
| 时间用区间而不是点 | `validity`（两端各带不确定范围）+ 整数 `from`/`to` 机械展开 |
| 时间支撑方式 | `temporalSupport: interval \| snapshot` —— 禁止在切片之间插值 |
| 审查独立于测试 | `review`，默认 `pending`；**软件测试不等于史料复核** |
| 几何编制留痕 | `compilation.method` 逐段写清是人工绘制还是取自哪套参照几何 |
| 缺口显式声明 | `COVERAGE` 13 条 + 「资料覆盖」面板 |
| 许可分级 | `Source.redistribution: allowed \| unknown \| denied` + `permissionEvidence` |
| 史实与解释分列 | 事件的 `summary`（已核验事实）与 `interpretation`（史家判断）分开 |
| 编制规范 | [`docs/EDITORIAL.md`](docs/EDITORIAL.md)，校验器逐条对应 |

另外并入了它的 **11 条机构来源**（MET、UNESCO、IDP、地方政府）和 **9 条东亚文化／制度事件**
（云冈石窟、龙门奉先寺、法隆寺、平城京、平安京、《金刚经》印本、百济覆亡、隋与高句丽战争、孙权称帝）
—— 本项目原有事件全是政治军事，这一组补上了宗教、技术与都城的维度，且都带真实机构来源。

它用的五级 `relation`（control/administration/vassal/influence/claim）与本项目的六级控制强度
是同一件事的两种切法；本项目保留了更细的六级，因为它能表达「羁縻」与「朝贡」的区别。

设计文档见 [DESIGN.md](./DESIGN.md)。

## 跑起来

```bash
npm install --cache ./.npm-cache   # 本机 ~/.npm 有权限问题，用本地缓存
npm run basemap && npm run regions # 拉 Natural Earth 底图并生成参照几何（产物已提交，一般不用跑）
npm run dev                        # http://localhost:5173
```

## 交付前必须跑

```bash
npm run verify
```

等于 `typecheck` + `check:data` + `check:points` + `build` 四道门。前两道是数据纪律的机械闸门：

- **`check:data`** —— 逐段校验：出处是否登记、时间区间是否合法、外环是否闭合、**是否自交**、同政权同层级的时空双重重叠、并存政权是否撞色。
  没有 `sourceId` 或指不到已登记来源的疆域段直接判 error，入不了库。
- **证据闸门** —— 每条疆域段／事件／地点必须至少有一条 `evidence` 且指向已登记来源；
  `redistribution=denied` 的来源必须写 `permissionEvidence`；`validity` 与整数区间必须自洽；
  `snapshot` 必须给 `snapshotYear`。
- **`check:points`** —— 把史地常识写成断言：洛阳在 230 年属曹魏、逻些在 750 年属吐蕃、敦煌在 800 年不属唐而属吐蕃、成都 330 年在成汉而非东晋、江陵 230 年属吴而不属魏，共 55 条。
  **比肉眼看图可靠得多**——点落测试抓出过六处真实的画歪（含「东晋在 330 年不该有巴蜀」这类断代错误）。
- `check:data` 还会逐个地点验证「它是否真的落在某个政权的面上」，专抓坐标画到海里或画到域外。

## 三条设计红线

1. **不做逐年插值动画，做「逐年状态机 + 状态迁移高亮」。**
   两个已知快照之间做几何插值，会凭空造出从未存在过的边界——那是伪造史料。数据被切成 51 个**状态区间**，区间内疆域完全不变；跨过边界时新增面淡入、消失面淡出，时间轴同步高亮该变更点。

2. **区分六级控制强度，而不是画一条线。**
   `直辖 / 军事控制 / 羁縻 / 朝贡 / 名义册封 / 一度深入`，填充与边界样式各不相同。朝贡级不填充、只画轮廓；`borderPrecision = 1` 的面永远画成柔化边缘——物理上不允许它长得像一条确定的国界。

3. **底图不含现代国界线。**
   用现代国界当底图会在用户脑中锚定错误的参照系，是这类项目最常见也最致命的硬伤。

## 边界是怎么画出来的

这是全项目最费工的部分，值得单说。**原则是：能用真实地理数据的地方就不要手画。**

参照几何集中在 `src/data/regions.ts`，由 `tools/gen-regions.mjs` 从 Natural Earth 10m 数据生成（`npm run basemap && npm run regions` 可再生），不是手写代码。

| 用在哪 | 依据 | 取法 |
|---|---|---|
| 海岸线、长江、淮河、汉水、黄河中段 | 10m 河道与海岸线中心线 | `route.mjs` 沿真实折线走 |
| 秦岭、阴山、昆仑 | 山脉区域多边形 | 按经度取南北缘**中线** |
| 长城线（辽东→敦煌） | 真实关隘与军镇 | 山海关、居庸关、张家口、大同、呼和浩特、包头、银川、兰州 |
| 成汉 | 四川盆地外环 | 直接可用 |
| 吐蕃 | 青藏高原外环 + 昆仑中线 | 高原本体，北界换昆仑 |
| 唐安西/北庭 | 塔里木盆地外环 + 天山北麓 | 盆地本体，北向加北庭、碎叶 |
| 后秦、前秦前期 | 黄土高原外环南缘 + 秦岭 | 北界取高原南缘 |
| 赫连夏 | 鄂尔多斯高原外环 | 南界下压以纳入统万城 |
| 渤海 | 松嫩平原外环东缘 | 加日本海一侧 |
| 东魏 / 西魏 | 黄河中段河道 | 两家共用同一条河，严丝合缝 |

顶点数 1361 → 3383。

三个坑值得记下来：

- **沿山脉多边形的边走会把盆地整块切出去。** 秦岭多边形的两条长边是北麓和南麓，沿任一条都行不通 —— 必须按经度取中线。
- **分界必须是同一条线。** 起初魏的南界走汉水、吴的北界走长江，中间就夹出一条江汉平原的空缝，江陵（在长江北岸）两边都不认。三国的西段南北界本来就在三峡汇合。
- **区域 ≠ 政权。** 黄土高原不包含长安（渭河平原在高原边缘以南），所以后秦 = 高原南缘（北界）+ 秦岭（南界）。直接把区域外环当政权轮廓会错。

**大别山没有用上** —— 它确实在参照数据里，但在 200–960 年这段政权格局里找不到任何一条边界是沿它走的（南北朝界在淮河，三国界在长江与荆州一线）。与其硬套，不如不用。

## 已经做完的

1. **海岸线与内陆边界贴向真实地理**（见上表）。
2. **城关层。** 67 处州治、关隘、军镇，按类型用不同图元（州治圆点 / 关隘金色菱形 / 军镇方块），带存废年代，低缩放只显示要冲。
3. **事件只画当年。** 时间轴走到哪，地图上就只有那一刻的纪事；没有纪事的年份显示「无纪事」并给出前后跳转。工具栏有 ⏮纪事 / 纪事⏭。
4. **补全十六国。** 汉赵、成汉、前凉、后秦、后燕、南燕、北燕、赫连夏、西秦、后凉、南凉、北凉、西凉共 13 个政权。410 年地图上有 11 个政权并立。
5. **用真实地理区域重画十六国与周边政权**（见上表）。

## 已知的粗（还没做完的）

- 梁、南齐、刘宋共用同一形状，未表现差异。
- 东晋 405–413 年谯纵割据、前秦 373–385 年领有益州这两段没有单列。
- 事件只有摘要与出处，没有详情正文；原因判断尚未逐条填进 `interpretation`。
- **页码级定位只有 9/136 条**，其余只到「书名／条目」级。

## 史料来源

- 谭其骧《中国历史地图集》（中国地图出版社 1982）—— 各卷作为疆域绘制的依据，人工重绘，未复制其数据
- CHGIS 中国历史地理信息系统 v6（哈佛大学 · 复旦大学）—— 治所点数据体系；其原始数据受学术非商业授权限制，本仓库未分发
- Natural Earth —— 海岸线、河流、湖泊，公有领域
- 正史文献：《三国志》《晋书》《资治通鉴》《隋书》《旧唐书》《新唐书》

每一段疆域、每一个事件都在数据文件里登记了 `sourceId`，构建期强制校验 —— **没有出处，进不了库**。
